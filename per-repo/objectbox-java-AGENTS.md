# ObjectBox — Java / Kotlin (Android, JVM desktop)

Instructions for AI coding agents working with ObjectBox in this repository.
Code examples are Kotlin; the Java equivalents follow the same rules.

Read [`objectbox-capabilities.md`](https://github.com/objectbox/agent-skills/blob/main/shared/objectbox-capabilities.md)
first — it holds the binding-agnostic constraints. This file holds what is
specific to Java/Kotlin. For Sync Server setup see
[`sync-server-setup.md`](https://github.com/objectbox/agent-skills/blob/main/shared/sync-server-setup.md).

## Before you write code

1. **Check the installed version.** Deprecations are silent in the wrong
   direction — training data is full of removed APIs.
   Current release: https://central.sonatype.com/artifact/io.objectbox/objectbox-android
2. **Run code generation.** Entities are annotations; the working code is
   generated by the Gradle plugin on build. Stale generated code produces
   errors that look like ObjectBox bugs.
3. **Look up the API, don't recall it.** Any docs page can be fetched as
   Markdown by appending `.md` — e.g. `https://docs.objectbox.io/queries.md`.

## 1. Entity declaration

```kotlin
@Entity
@Sync
data class Conversation(
    @Id var id: Long = 0,
    @Index var userId: String = "",
    var title: String = "",
    var status: String = "active",
    var updatedAt: Long = System.currentTimeMillis()
)
```

- `@Sync` is **class-level**. Placing it on a property either fails codegen or
  is silently ignored — the entity is then simply not synced and nothing says so.
- Index the properties you filter or sort on.

## 2. ToOne relations — the JVM initialization trap

**Wrong — `lateinit` breaks on Kotlin desktop/JVM:**

```kotlin
class Message(...) {
    @Transient @JvmField var __boxStore: BoxStore? = null
    lateinit var conversation: ToOne<Conversation>   // never initialized
}
```

**Correct — inline initialization:**

```kotlin
class Message(...) {
    @Transient @JvmField var __boxStore: BoxStore? = null
    var conversation: ToOne<Conversation> = ToOne(this, Message_.conversation)
}
```

Rules:
- Declare `@Transient @JvmField var __boxStore: BoxStore? = null` in every
  non-`data class` that has relations.
- Always initialize `ToOne` inline.
- Never use `lateinit` for a `ToOne` on Kotlin desktop/JVM.

## 3. When to call `attach()`

`box.attach(entity)` sets `__boxStore` so `ToOne.get()` can resolve its target.

- If you set the relation and do **not** hand the entity back to callers,
  `attach()` is unnecessary.
- If you return an entity and callers may call `.get()` on a relation, attach
  before returning.

## 4. Do not mirror a relation as a plain `Long`

Sync remaps relation IDs. It does **not** remap a hand-maintained mirror field.

```kotlin
// Risky — dual tracking
class Message(
    @Index var conversationId: Long = 0,   // manual mirror
    ...
) {
    var conversation: ToOne<Conversation> = ToOne(this, Message_.conversation)
}
```

Safe options:
- **A:** use only the `ToOne`.
- **B:** keep the plain `Long` only if the parent uses
  `@Sync(sharedGlobalIds = true)` and you can guarantee uniqueness.

Note: a `ToOne` is stored internally as a generated `<relationName>Id` property.
Querying `Message_.conversationId` when it *is* that backing ID is fine. What is
forbidden is an additional, manually maintained mirror field.

## 5. Cascade deletes are manual — and must be complete

ObjectBox does not cascade. Orphans are silent.

```kotlin
fun deleteConversation(conversationId: Long): Boolean {
    val conversation = conversationBox.get(conversationId) ?: return false
    store.runInTx {
        messageBox.query().equal(Message_.conversationId, conversationId).build().remove()
        contextBox.query().equal(ContextPack_.conversationId, conversationId).build().remove()
        summaryBox.query().equal(Summary_.conversationId, conversationId).build().remove()
        conversationBox.remove(conversation.id)
    }
    return true
}
```

- Wrap the cascade in `store.runInTx {}`.
- Use `.build().remove()` — do not load-to-delete.
- Include **every** referencing entity type.

## 6. Assignable IDs with Sync

```kotlin
@Entity
@Sync(sharedGlobalIds = true)
data class ManualDocument(
    @Id(assignable = true) var id: Long = 0,
    ...
)
```

- `@Id(assignable = true)` alone is **not** enough — without
  `sharedGlobalIds = true` IDs may be remapped.
- `sharedGlobalIds` is immutable after first deployment.
- Only use it when global uniqueness across devices is guaranteed.

## 7. Local-only entities in a sync store

Entities without `@Sync` are local-only.

- Do not create relations across the sync/local boundary.
- A plain ID reference from a local entity to a synced one is only safe if the
  synced entity uses `sharedGlobalIds = true`.
- **You cannot add `@Sync` to an entity that already holds data.** There is no
  migration path — server and client stores must be wiped. This is destructive.

## 8. Persisted state

- Do not overload fields (e.g. bumping a `version` field just to "touch" sync).
- If state must survive re-creation, give it a dedicated field.

## 9. Reactive updates — no polling loops

If you feel the urge to write `while (true) { sleep(); query() }`: don't.

```kotlin
private var subscription: DataSubscription? = null
private var query: Query<Conversation>? = null

fun startObserving(onUpdate: (List<Conversation>) -> Unit) {
    query = conversationBox.query(Conversation_.status.equal("active")).build()
    subscription = query!!
        .subscribe()
        // .on(AndroidScheduler.mainThread())   // Android UI thread
        .observer { data -> onUpdate(data) }
}

fun stopObserving() {
    subscription?.cancel(); subscription = null
    query?.close();         query = null
}
```

- Keep a reference to the `DataSubscription` until cancelled.
- For a plain "something changed" signal, use `BoxStore.subscribe(MyEntity::class.java)`.

## 10. Vector search (HNSW)

```kotlin
@HnswIndex(
    dimensions = 384L,
    distanceType = VectorDistanceType.COSINE,
    neighborsPerNode = 30,
    indexingSearchCount = 200
)
var embeddingVector: FloatArray? = null
```

```kotlin
val maxCount = (limit * 8).coerceAtLeast(40)
val q = chunkBox.query(
    Chunk_.embeddingVector.nearestNeighbors(queryVector, maxCount)
).build()
val results = q.findWithScores()
q.close()
// score is a DISTANCE — lower is better
```

- Dimensions are required and must match your embedding output exactly.
- Default distance is (squared) Euclidean. For sentence embeddings set cosine
  explicitly.
- When combining nearest-neighbor with a selective filter, **over-fetch**
  (larger `maxCount`) or you get too few matches back.
- Never write a manual cosine scan over all rows in production.

**Vectors and Sync:** embeddings sync as normal entity data — the
"sync the text, recompute vectors locally" workaround is not needed. Put the
embedding on the same synced entity as its metadata. Keep dimensions stable; to
change models, add a new property and migrate deliberately. HNSW is a *local*
index — it updates as objects arrive; do not try to sync the index. Watch payload
size: large vectors increase sync traffic.

## 11. Query lifecycle

```kotlin
conversationBox.query()
    .equal(Conversation_.userId, userId)
    .orderDesc(Conversation_.updatedAt)
    .build()
    .use { q -> q.findFirst() }
```

- Use `use {}` for short-lived queries.
- Cache and reuse long-lived queries only inside repository/data-access code.

## 12. Sync client — "pull updates" is built in

```kotlin
val syncClient = Sync.client(
    boxStore,
    "wss://your-server:9999",
    SyncCredentials.none()      // dev only
).buildAndStart()
```

- Sync sends and receives automatically once started. Do not add a fetch loop.
- A started client cannot be started again — stop/close and build a new one.
- Use event listeners for connection status in the UI, not polling.
- `SyncCredentials.none()` pairs with a server started
  `--unsecured-no-authentication`, which is **loopback development only**. For
  anything else use the shared-secret credentials form and never commit the
  secret. See [`sync-server-setup.md`](https://github.com/objectbox/agent-skills/blob/main/shared/sync-server-setup.md).

## 13. Gradle — sync vs. non-sync plugin

```kotlin
apply(plugin = "io.objectbox.sync")   // sync-enabled
```

Apply native runtimes in the consuming modules (Android / desktop), not in a
shared module. The sync-enabled native library is a **different artifact**, not a
flag — using the non-sync library with `@Sync` entities fails at write time with
`"sync has not been activated"`.

## 14. Model file

`objectbox-models/default.json` carries stable UIDs that Sync depends on.

- Commit it.
- Never delete or regenerate it to fix an error.
- After any schema change, follow [`sync-server-setup.md`](https://github.com/objectbox/agent-skills/blob/main/shared/sync-server-setup.md)
  to update the server. A stale server model produces errors like
  `"Relations not allowed"`.

## Quick reference — common mistakes

| Mistake | Why it breaks | Fix |
|---|---|---|
| `@Sync` on a property | class-level annotation; silently not synced | move it to the class |
| Polling loop to "refresh" | duplicates observers, wastes CPU | `Query.subscribe()` / `BoxStore.subscribe()` |
| Custom "pull updates" job | duplicates Sync, races | start Sync, listen to events |
| Manual cosine scan | unbounded, defeats HNSW | `nearestNeighbors(...)` |
| `lateinit ToOne` on JVM | relation never initialized | inline `ToOne(this, ...)` |
| Mirror `Long` FK on a synced relation | Sync remaps relations, not mirrors | use `ToOne` or `sharedGlobalIds` |
| Unclosed query | leaks in long-running apps | `use {}` or close explicitly |
| Treating score as similarity | score is a distance | invert before ranking |
| Non-sync native lib + `@Sync` entities | writes fail: "sync has not been activated" | use the sync-enabled build |
| Stale server model JSON | server crashes | re-copy after every schema change |
| Adding `@Sync` to an entity with data | unsupported migration | wipe server + clients, or model anew |
